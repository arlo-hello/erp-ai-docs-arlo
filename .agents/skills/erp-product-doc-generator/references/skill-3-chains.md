# 技能3：业务链路串联（含用户故事地图）

> ⚠️ **示例隔离声明**：本文档中所有事件名、字段名、表格数据、线框图等均为演示示例——禁止直接复制到真实需求输出中。真实输出必须基于实际需求分析和代码侦察结果。

**角色**：你是一位擅长流程建模和场景化思维的产品经理。

**参考方法论**：价值流图、用户旅程地图、用户故事地图、场景化思维

**输入**：技能1事件清单（含影响性标记），技能2影响性结论（含库存节点数要求）

**任务**：先用用户故事地图按时间线组织用户活动，再基于事件 I/O 串联泳道图。**仅绘制 🟢本期实现 的事件。🔴本期不做 的事件跳过**——如果跳过导致链路中断，须标注"因事件X标记为🔴，链路从Y到Z的连接为手动流程或本期不覆盖"。

---

## 思考步骤

**用户故事地图**：
1. 按时间线组织用户活动（活动 → 任务 → 子任务）。
2. 覆盖正常流程和异常分支，确保用户完整操作路径无遗漏。
3. **区分操作模式**：批量模式（勾选N个→一键执行）和单个模式（进入详情页→执行）必须各自有独立子任务，标注 `[批量模式]` / `[单个模式]`。
4. 每个子任务对应技能1的一个🟢事件。

**业务链路泳道图**：
5. 🔴 **并行链路识别**：如果存在两条或多条并行业务链路（如采购发货→入库→内采 vs 备货发货→入库→内采），每条链路必须独立展开。不能因为"链路B与链路A类似"而跳过链路B的完整分析。每条并行链路：独立的故事地图子任务、独立的泳道图节点、独立的功能点。
6. 确定每条链路的起点和终点事件（仅🟢事件）。
7. 按照"上游输出 = 下游输入"串联所有🟢事件。
8. I/O 不匹配时标注断裂点。
9. 补充异常分支（至少3个）。
10. 画**角色泳道图**（每个泳道=一个角色）。
11. 画**领域泳道图**（每个泳道=一个领域）。
12. 为每个节点标注**单据流转三元组**。
13. **空泳道告警** 🔴：领域泳道图各泳道必须有节点。库存域节点数 ≥ 技能2传递的库存变更节点数。空泳道→回溯技能1补连锁事件。
14. 🔴 **子单据独立化**：如果某个事件输出多个单据，且后者有独立生命周期，作为独立子链路展开。
15. 🔴 **部分完成场景**：对每个状态变更事件，追问「如果只完成了一部分，状态如何流转？」——部分收货（实收<预报）/ 部分退货 / 部分付款 / 部分发货。事件模型默认"全部完成"，但现实是"部分完成才是常态"。**部分完成场景不是异常分支——是独立的正向流程路径，需要独立的泳道节点和状态值。** 常见遗漏：拆分包裹（3个包裹2签收1丢失→订单状态？）、分批入库（预报100只收了80→剩下的20怎么办？）、部分退货（退了5件，剩下95件继续走流程还是暂停？）。

### 业务链路泳道图

**角色泳道图**和**领域泳道图**均使用 Mermaid 语法。两张图都必须画。

🔴 **逆向链路呈现要求**：逆向操作必须以独立节点在泳道图中呈现。节点标注：触发条件+级联作废路径+不可逆条件。

🔴 **补偿路径呈现要求**：系统触发-补偿事件必须在领域泳道图中以独立补偿路径呈现——从失败点画出回滚箭头，标注回滚的库存节点和触发条件。

🔴 **Mermaid 兼容语法（源头约束——必须在技能3产出时就遵守，下游不做转换）**：
- 序列图不使用 `actor`（部分渲染器不支持），改用 `participant`
- 不使用 `-->>` 虚线箭头，改用 `->>` 实线箭头
- 流转图不使用 `-.->` 虚线过渡，改用 `-->`
- 状态图状态名不使用中文+下划线（如`未预报_未发货`），使用短ID（如`s00`）+ `note` 标注中文语义
- 不在节点/箭头上使用特殊字符（`≠` `≥` `≤`），改用中文表述

### 单据流转三元组（每个节点标注）

```
节点: 仓库已收货
  输入单据: 入库预报单(预报单号, SKU, 预报数量)
  输出单据: 入库单(入库单号, 实收数量, 批次号)
  状态变更: 入库预报单 部分收货 → 全部收货
```

每个业务场景走四段：当前流程→修正流程→目标流程→异常分支。

## 质量标准

- 用户故事地图：活动→任务→子任务层级清晰。批量/单个已区分。
- 泳道图起点和终点明确，覆盖至少3个异常分支。
- **双视图泳道**：角色+领域两张图。
- **单据流转三元组**：每个关键节点标注。
- **空泳道检查**：所有领域泳道有节点，库存域节点数≥技能2传递的最小节点数。
- **逆向链路**：正向操作的逆向已在泳道图中呈现。
- 🔴 **部分完成**：关键状态变更（收货/发货/付款）的部分完成场景已在泳道图中呈现。部分收货/部分退货/部分付款的状态值已定义。
- 🔴 **N:1 聚合取消影响**：从技能1的「N:1 聚合逆向清单」提取每条 N:1 聚合链，在泳道图中补充"成员取消"分支路径——全部成员未执行下一步→全取消→聚合实体作废→重建只含剩余成员；任一成员已执行下一步→禁止取消。库存域需同步扣减对应的未发货库存（目的仓）。
- 每个节点可追溯到技能1事件。
