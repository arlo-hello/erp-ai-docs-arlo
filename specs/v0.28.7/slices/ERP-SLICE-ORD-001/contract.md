# ERP-SLICE-ORD-001 接收样机申请并完成自动或人工推仓契约

- slice_id: ERP-SLICE-ORD-001 | status: DEFINED
- business_outcome: 样机申请进入 ERP 后按“是否自动交运”得到唯一、可追溯的办理结果
- blocked_by: []

## 改造范围

新增样机申请接收记录、幂等与版本控制；自动路径执行样机 Workflow 和推仓动作；非自动路径生成“待推送”样机出库单，允许空字段保存，补齐后复用现有推送能力。

## 业务规则

1. 同一申请号只能有一个有效办理实例，旧版本不得覆盖新结果。
2. 自动交运=是时执行 Workflow；自动交运=否时不得执行 Workflow。
3. 待推送保存可缺仓库、库区、物流渠道、主体、渠道或区域；推送前必须补齐现有出库必填字段。
4. 接收与 Workflow 匹配不占用库存；正式单按既有规则占用。
5. 结果不明只查 WMS，不直接重推。
6. 样机申请审批通过后自动推送 ERP；重复审批事件按申请号与版本幂等。
7. 仅当关联出库流水所有商品实发数量均为 0 时允许样机侧取消或编辑；任一商品实发数量大于 0 时必须拒绝并返回明确提示。
8. 取消将原接收记录、样机出库单、出库流水及未出库 WMS 任务置入同一取消链；WMS 已接单时须确认取消后才完成。
9. 编辑必须先完成旧链路取消，修改后重新审批；审批通过后以递增版本自动推送并建立新链路。
10. Workflow 新增“样机出库”触发器和“样机出库推仓”动作；动作的仓库、库区、物流渠道、主体、渠道、区域均必填，物流渠道与库区只能取所选仓库下的有效项。
11. 动作“是否推送至仓库”默认开启：开启时复用样机出库详情页“推送”的同一领域能力；关闭时不调用 WMS，沿用既有不推仓出库逻辑，将样机出库单置为已出库并按明细更新 ERP 库存。
12. 仓库变更必须清空库区与物流渠道；执行实例使用已发布 Workflow 版本快照，配置变更不得影响历史实例。
13. 关闭推仓路径的单据状态与库存更新必须在同一事务内完成，失败时整体回滚并登记异常。

## 测试边界

- 独立验证声明：是
- 包含：审批触发、接收、分流、Workflow 触发器与动作配置、仓库联动、推仓开关、待推送编辑、推送、幂等、零实发守卫、级联取消、编辑后重新审批推送。
- 不包含：飞书真实写入、多 WMS 发货单汇总；分别由其他切片验证。

## 依赖与 Mock 策略

- 前置切片：无。
- 外部样机系统：以固定契约 mock 申请号、版本和是否自动交运。
- WMS：以 mock 覆盖成功、明确失败、超时后查到、超时后查无四种结果。
- 验证顺序：先 unit 校验状态守卫，再 feature 校验事务与幂等，最后 E2E 使用外部 mock。
