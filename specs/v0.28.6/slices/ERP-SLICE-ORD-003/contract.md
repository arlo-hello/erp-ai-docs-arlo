# ERP-SLICE-ORD-003 履约工作流可用假设渠道连续判定并安全切换正式渠道

- slice_id: ERP-SLICE-ORD-003
- status: DEFINED
- business_outcome: 缺少物流渠道的履约单可在 Workflow 中获得本次执行有效的假设渠道，并由正式渠道安全覆盖。
- blocked_by: [ERP-SLICE-ORD-002]
- 切片类型：vertical

## 改造范围

| 能力 | 现状 | 改造内容 |
|---|---|---|
| 动作配置 | 无假设渠道动作 | 新增动作及必填仓库、必填物流，物流按仓库联动 |
| 连续编排 | 履约画布可连续添加节点 | 该动作后可添加条件或动作，不新增成功/失败分支 |
| 执行上下文 | 无假设渠道生命周期 | 新增当前履约单本次执行级临时渠道及来源 |
| 正式覆盖 | 后续动作可确定履约数据 | 仓库物流成对产生时原子覆盖 |
| 审计 | 无假设与覆盖链 | 保存假设值、生效节点、正式值和覆盖节点 |

## 数据模型变更

| 数据对象 | 变更 | 约束 |
|---|---|---|
| Workflow 动作定义 | 新增动作及两个枚举字段 | 两字段必填且物流属于仓库 |
| Workflow 执行上下文 | 新增临时渠道与来源 | 不写履约单正式字段，不跨单或跨执行 |
| Workflow 执行历史 | 扩展假设与覆盖审计 | 每次执行新增记录，不覆盖历史 |

## API 端点

复用既有 Workflow 动作列表、仓库枚举和按仓库查询物流的入口，不新建平行入口；响应需包含动作字段定义、必填标识和联动信息。

## 业务规则

1. 动作仅展示仓库和物流，均为必填。
2. 未选仓库时物流不可选；切换仓库后清空旧物流，只展示该仓库下有效物流。
3. 假设组合只注入当前履约单本次 Workflow 执行上下文，不写正式字段。
4. 动作后可继续添加条件或动作，不存在成功与失败分支。
5. 正式仓库与物流成对产生后原子覆盖假设组合。
6. 半覆盖、停用、删除或解除关联时明确报错并立即终止整个 Workflow，不执行后继节点。
7. 审计保存假设值、来源、生效节点、正式值和覆盖节点；重跑不覆盖历史。

## 测试边界

- 独立验证声明：是
- unit：生命周期、履约单隔离、来源优先级、原子覆盖。
- feature：元数据、必填、联动、拓扑、异常矩阵、审计。
- E2E：假设动作后接 Mock 条件与动作，验证连续传递、覆盖和异常终止。
- 不验证 ERP-SLICE-ORD-002 的计费重量公式，只验证提供渠道上下文。
