# 样机申请可自动建单推仓并形成异常闭环

- slice_id: ERP-SLICE-ORD-002
- 来源 Issue: ERP-210
- 切片类型: vertical
- 状态: DEFINED

## 业务结果

ERP 接收并记录样机申请，自动匹配 Workflow 并推仓；Workflow 未命中或推仓异常时回传并写入一次飞书快照；取消请求按实际出库结果判定。系统联调保证不存在“推送后 ERP 接收失败且可识别”的业务分支。[来源：ERP-210 第 1-5 条；确认 D1-D4；需求调整 2026-11-25]

## 范围

- 包含：样机触发器、条件、推仓动作、接收幂等、匹配推仓、异常回传、异常一次性快照和取消校验。
- 不包含：样机系统内部功能、正常单据飞书同步、异常快照持续更新、飞书侧重试。
- 不包含：ERP 接收失败且可识别的业务分支，以及由该分支产生的回传和飞书记录。

## 验收标准

| AC | 验收结果 | 验证方式 |
|---|---|---|
| AC-001 | 首次推送保存接收记录；相同申请单号重复推送不重复生成单据或推仓 | feature：重复请求两次，断言接收记录和单据链各一份 |
| AC-002 | 命中 Workflow 时按动作配置推仓并关联样机出库单与出库流水 | feature：mock 仓库成功响应，断言命中、推仓和单据关联 |
| AC-003 | 未命中时终止办理、回传原因并新增一条飞书异常快照 | feature：构造无匹配规则，mock 两个外部系统并断言内容与次数 |
| AC-004 | 推仓失败或结果未知时不按成功继续办理，回传异常并新增一条快照 | feature：分别 mock 失败与未知，断言后续未继续且飞书写入一次 |
| AC-005 | 正常接收、命中、推仓成功和出库完成均不写飞书 | feature：执行成功主链路，断言飞书 mock 调用为零 |
| AC-006 | 同一次异常不重复新增；写入后状态变化不更新原记录 | feature：重复触发并推进状态，断言飞书仅一次新增且无更新 |
| AC-007 | 无实际出库商品时取消成功并取消未出库任务及关联单据链 | feature：实际出库量均为零，mock 仓库取消并断言链路取消 |
| AC-008 | 任一商品已有实际出库时拒绝取消并保留单据链 | feature：一项出库量大于零，断言拒绝原因与状态不变 |
| AC-009 | 项目选择受 TAP 数据权限约束 | E2E：以不同项目权限账号验证选项范围和保存校验 |
| AC-010 | 业务流程和飞书同步均不包含“ERP 接收失败且可识别”分支 | 契约测试：断言异常枚举和飞书触发条件仅包含 Workflow 未命中、推仓失败、推仓结果未知 |

## 测试边界

- 独立验证声明：是
- 使用样机系统、仓库系统和飞书 mock，可在无其他未合入切片时验证全部 AC。
- 验证顺序：Workflow 配置 → 接收幂等 → 成功主链路 → 异常分支 → 飞书快照 → 取消分支。
- 不验证样机系统、仓库系统内部页面及飞书人工编辑。
- 不模拟 ERP 接收失败业务分支；系统间传输技术故障由联调与通用基础设施测试覆盖。

## 依赖与 Mock 策略

| 依赖 | 策略 |
|---|---|
| 现有 ERP Workflow | 测试库配置触发器、条件和动作 |
| 现有样机出库能力 | 工厂数据创建并断言关联状态 |
| 样机系统 | mock 推送、异常接收和取消请求 |
| 仓库系统 | mock 推仓成功、失败、结果未知和取消响应 |
| 飞书 | mock 新增快照，并断言不调用更新接口 |

## 业务不变量

1. 同一申请单号不得产生重复 ERP 单据或重复推仓。
2. 正常链路不得写飞书。
3. 同一次异常只写一条快照，写入后不持续更新。
4. 任一商品已有实际出库时不得取消关联单据链。
