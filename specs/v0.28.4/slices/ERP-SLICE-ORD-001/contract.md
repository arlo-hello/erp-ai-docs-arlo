# ERP-SLICE-ORD-001 履约申报规则精细化契约

- slice_id: ERP-SLICE-ORD-001
- `business_outcome`: 用户可在现有 workflow 条件组按仓库选择物流渠道，并将固定总金额按产品分类及运行时实际 SKU 两级分摊，生成全行截断且推仓后冻结的申报快照。
- `blocked_by`: `[]`
- 切片类型：implementation

## 验收标准

| AC | 可观察结果 | 验证方式 |
|---|---|---|
| AC-001 | 申报比例允许 `0.1%～100.0%` 且最多一位小数；0、负数、超过100和两位小数被前后端拒绝 | unit 校验边界；feature 验证接口；E2E 验证表单 |

| AC-003 | 新增物流渠道不改变现有 workflow 条件求值和履约动作执行顺序，不新增三维规则引擎 | unit 回归条件组合；feature 回归既有 workflow |
| AC-004 | 条件节点独立展示描述、且/或关系、条件组新增/删除、条件字段、计算符号、输入值和条件行删除；“物流渠道”只新增到条件字段选项，且其计算符号仅允许“等于（=）”“不等于（≠）”；条件节点不展示履约动作字段 | frontend component 验证字段、按钮及计算符号枚举；E2E 验证新增、删除、且/或、等于、不等于和保存 |

| AC-009 | 拆单、换仓产生的新履约单按自身上下文重新命中并计算；推仓后原单申报快照不可原地修改，取消并重建后新单重新计算 | feature 覆盖拆单/换仓/冻结；E2E 覆盖取消重建主链路 |

## 测试边界

- 独立验证声明：是
- 包含：独立条件节点线框、独立履约动作节点线框、workflow 条件组物流渠道依赖、仓库渠道级联、比例精度、两位小数固定总金额、分类分摊行、SKU 二级分摊单选、全履约行截断、异常、拆单换仓重算、推仓冻结。
- 不包含：目的国免税阈值主数据、税则自动判断、仓库系统改造、已推仓原单原地修改。
- unit 聚焦输入边界、条件组合、分类→SKU 两级分摊、全行截断余量和确定性；feature 覆盖配置接口、履约事务、拆单换仓和冻结；E2E 覆盖用户配置及取消重建主链路。

## 依赖与 Mock 策略

- 前置切片：无；`blocked_by: []`。
- 现有数据依赖：仓库—物流渠道绑定、产品分类与 SKU 关联、履约行数量、销售价格与币种。均来自现有系统，不依赖未合入的同版本切片。
- 外部仓库系统：合并前使用 explicit mock 验证推仓载荷中的行申报值、币种、失败重试及快照冻结；不要求真实仓库环境通过本切片 AC。
- Mock 边界：mock 仅替代仓库接收端，不替代本系统的规则命中、金额计算、事务写入或状态校验。
- 验证顺序：unit 条件依赖、两级分摊与全行截断 → backend feature → frontend component/E2E → mock 仓库接口集成 → 取消重建回归。
