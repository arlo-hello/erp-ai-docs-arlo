# ERP-SLICE-ORD-001 履约申报规则精细化契约

> 状态：`DEFINED`，待人工评审；金额存储与外部接口精度完成技术评审后方可晋升 `READY`。

## 基本信息

- slice_id: ERP-SLICE-ORD-001
- `business_outcome`: 用户可在现有 workflow 条件组按仓库选择物流渠道，并以一位小数比例或两位小数固定金额、SKU 占比生成全行截断且推仓后冻结的申报快照。
- `blocked_by`: `[]`
- 切片类型：implementation

## 验收标准

| AC | 可观察结果 | 验证方式 |
|---|---|---|
| AC-001 | 申报比例允许 `0.1%～100.0%` 且最多一位小数；0、负数、超过100和两位小数被前后端拒绝 | unit 校验边界；feature 验证接口；E2E 验证表单 |
| AC-002 | 同一条件组不存在已选值的发货仓库条件时物流渠道不可选；存在时仅展示该仓绑定且启用的渠道；AND/OR 均执行此依赖，删仓、清空或换仓后清理失效渠道 | feature 验证枚举与保存校验；E2E 分别验证 AND/OR、删仓、清空和换仓 |
| AC-003 | 新增物流渠道不改变现有 workflow 条件求值和履约动作执行顺序，不新增三维规则引擎 | unit 回归条件组合；feature 回归既有 workflow |
| AC-004 | 履约动作只允许“比例申报/固定金额”二选一；固定金额大于0且最多两位小数；非当前方式字段不参与执行 | unit 验证动作解析；feature 验证新旧配置兼容；E2E 验证切换 |
| AC-005 | 固定金额小卡片支持从启用商品中模糊搜索且 SKU 不重复；固定申报占比单项 `0.1～100`、0 无效、合计为100 | unit 验证占比；feature 验证启用状态与保存校验；E2E 验证搜索、增删行和错误提示 |
| AC-006 | 固定金额按 SKU 配置占比计算申报单价；所有履约行采用截断法，不按行排序、不设置末行承差，截断余量不回填；重复执行结果一致 | unit 参数化验证算法、截断余量与幂等；feature 验证履约行落值 |
| AC-007 | 履约 SKU 未配置、配置 SKU 不属于履约单、SKU 数量非法、币种为空或多币种时整体失败，不产生部分写入，并记录可识别异常进入人工处理 | unit 验证异常分支；feature 验证事务回滚与异常记录 |
| AC-008 | 拆单、换仓产生的新履约单按自身上下文重新命中并计算；推仓后原单申报快照不可原地修改，取消并重建后新单重新计算 | feature 覆盖拆单/换仓/冻结；E2E 覆盖取消重建主链路 |
| AC-009 | 推仓载荷使用冻结后的履约行申报值与币种，外部接口失败不改变已计算快照 | feature 使用 explicit mock 仓库接口验证载荷、重试与快照不变 |

## 测试边界

- 独立验证声明：是
- 包含：workflow 条件组物流渠道依赖、仓库渠道级联、比例精度、两位小数固定金额、启用 SKU 搜索、SKU 占比、全履约行截断、异常、拆单换仓重算、推仓冻结。
- 不包含：目的国免税阈值主数据、税则自动判断、仓库系统改造、已推仓原单原地修改。
- unit 聚焦输入边界、条件组合、SKU 占比、全行截断余量和确定性；feature 覆盖配置接口、履约事务、拆单换仓和冻结；E2E 覆盖用户配置及取消重建主链路。

## 依赖与 Mock 策略

- 前置切片：无；`blocked_by: []`。
- 现有数据依赖：仓库—物流渠道绑定、产品状态与 SKU、履约行数量与币种。均来自现有系统，不依赖未合入的同版本切片。
- 外部仓库系统：合并前使用 explicit mock 验证推仓载荷中的行申报值、币种、失败重试及快照冻结；不要求真实仓库环境通过本切片 AC。
- Mock 边界：mock 仅替代仓库接收端，不替代本系统的规则命中、金额计算、事务写入或状态校验。
- 验证顺序：unit 条件依赖、占比与全行截断 → backend feature → frontend component/E2E → mock 仓库接口集成 → 取消重建回归。
