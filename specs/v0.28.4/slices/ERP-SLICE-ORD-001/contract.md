# ERP-SLICE-ORD-001 履约申报规则精细化契约

> 状态：`DEFINED`，待人工评审；金额存储与外部接口精度完成技术评审后方可晋升 `READY`。

## 基本信息

- slice_id: ERP-SLICE-ORD-001
- `business_outcome`: 用户可按仓库、目的国家和物流渠道配置履约申报规则，并以一位小数比例或固定总额生成金额守恒、推仓后冻结的申报快照。
- `blocked_by`: `[]`
- 切片类型：implementation

## 验收标准

| AC | 可观察结果 | 验证方式 |
|---|---|---|
| AC-001 | 申报比例允许 `0.1%～100.0%` 且最多一位小数；0、负数、超过100和两位小数被前后端拒绝 | unit 校验边界；feature 验证接口；E2E 验证表单 |
| AC-002 | 物流渠道条件必须基于已选仓库，仅展示该仓绑定且启用的渠道；换仓后旧渠道被清理或阻止保存 | feature 验证枚举与保存校验；E2E 验证级联 |
| AC-003 | 仓库、目的国家、物流渠道复用 workflow AND/OR；执行时读取已确定的仓库与渠道，不形成循环依赖 | unit 验证条件组合；feature 验证执行顺序 |
| AC-004 | 履约动作只允许“申报比例/固定总额”二选一，非当前方式字段不参与执行 | unit 验证动作解析；feature 验证新旧配置兼容；E2E 验证切换 |
| AC-005 | 固定总额按履约数量占比分摊，前 N-1 行截断、按履约行 ID 升序的最后一行承接尾差，重复执行结果一致且行金额合计严格等于固定总额 | unit 参数化验证算法与幂等；feature 验证履约行落值 |
| AC-006 | 总数量为0、参与行数量非法、币种为空或多币种时整体失败，不产生部分写入，并记录可识别异常进入人工处理 | unit 验证异常分支；feature 验证事务回滚与异常记录 |
| AC-007 | 拆单、换仓产生的新履约单按自身上下文重新命中并计算；推仓后原单申报快照不可原地修改，取消并重建后新单重新计算 | feature 覆盖拆单/换仓/冻结；E2E 覆盖取消重建主链路 |
| AC-008 | 推仓载荷使用冻结后的履约行申报值与币种，外部接口失败不改变已计算快照 | feature 使用 explicit mock 仓库接口验证载荷、重试与快照不变 |

## 测试边界

- 独立验证声明：是
- 包含：workflow 物流渠道条件、仓库渠道级联、比例精度、固定总额分摊、异常、拆单换仓重算、推仓冻结。
- 不包含：目的国免税阈值主数据、税则自动判断、仓库系统改造、已推仓原单原地修改。
- unit 聚焦输入边界、条件组合、分摊守恒和确定性；feature 覆盖配置接口、履约事务、拆单换仓和冻结；E2E 覆盖用户配置及取消重建主链路。

## 依赖与 Mock 策略

- 前置切片：无；`blocked_by: []`。
- 现有数据依赖：仓库—物流渠道绑定、产品申报价、履约行数量与币种。均来自现有系统，不依赖未合入的同版本切片。
- 外部仓库系统：合并前使用 explicit mock 验证推仓载荷中的行申报值、币种、失败重试及快照冻结；不要求真实仓库环境通过本切片 AC。
- Mock 边界：mock 仅替代仓库接收端，不替代本系统的规则命中、金额计算、事务写入或状态校验。
- 验证顺序：unit 分摊与条件 → backend feature → frontend component/E2E → mock 仓库接口集成 → 取消重建回归。
