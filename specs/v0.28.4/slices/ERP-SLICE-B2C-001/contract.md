# ERP-SLICE-B2C-001 多张原履约单可安全组合为一次仓库履约

## 基本信息

- slice_id: ERP-SLICE-B2C-001
- `business_outcome`: 操作员可把严格同构的多张未推仓原履约单组合为一次仓库履约；库存不重复占用，原订单和售后归属不丢失，仓库只接收一次推送，Shopify 各原单最终同步成功。
- `blocked_by`: `[]`
- 切片类型：implementation

## 测试边界

- 独立验证声明：是
- 包含：人工组合、用户点击触发的自动组合批次、组合单号生成、资格校验、组合聚合根、成员映射、原履约单双维状态、成员履约状态同步、原履约操作与订单取消拦截、编辑/退款过滤、库存凭证原子替换、唯一推仓、WMS 状态、出库回调、共享运单、Shopify 成员同步、逆向重建、权限、并发和审计。
- 不包含：等待窗口、后台定时或无人触发自动组合、修改 Shopify、已出库撤销、仓库真实环境联调。
- unit：资格比较、自动分组等价键、编号格式与扩位、组合状态与履约状态映射、操作决策、库存守恒、同步聚合和幂等分类。
- feature：自动批次范围与结果、编号并发唯一性、事务、权限、成员竞争、API、外部结果未知和补偿。
- E2E：手工选择或自动组合→组合创建→推仓→出库→平台同步，以及取消重建主链路。

## 依赖与 Mock 策略

- 前置切片：无；不得依赖其他未合入的 v0.28.4 切片。
- WMS：以显式 mock 覆盖接单成功、业务拒绝、超时结果未知、整单取消成功/失败、重复/乱序出库回调、明细冲突。
- Shopify：以显式 mock 覆盖每成员成功、限流、超时、原单状态冲突及重试后成功；断言调用只包含该成员原单商品行。
- 库存：使用真实事务仓储完成 feature 测试；对故障点注入异常并断言占用净变化为零。
- 编号服务：Redis 使用可控测试实例覆盖原子递增、缓存丢失和跨日；数据库使用真实唯一索引验证并发冲突重试，不以 mock 代替唯一性验证。
- 售后：显式 mock 退款/取消请求，分别验证未出库重建与已出库不改发运事实。
- 验证顺序：unit → backend feature/并发 → frontend component → WMS/Shopify mock contract → E2E。
