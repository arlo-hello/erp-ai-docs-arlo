# ERP-SLICE-PUR-001 多张采购发货单可合并预报并完整入库契约

> 状态保持 `DEFINED`，等待人工评审；前后端以本契约共同实现一个垂直切片。

## 基本信息

- slice_id: ERP-SLICE-PUR-001
- business_outcome: 同仓多张采购发货单只生成一张采购入库单，来源关系、供应商、状态、确认和取消均可完整追溯。
- blocked_by: `[]`
- 切片类型：implementation

| AC | 可观察结果 | 验证方式 |

## 测试边界

- 独立验证声明：是
- 包含：跨页选择、合并预报、来源关系、供应商展示、整单确认、整单取消、并发、幂等、WMS 补偿和单单兼容。
- 不包含：采购单拆分规则修改、发货单创建规则修改、跨仓合并、已确认入库后的拆单、线稿图片制作。
- unit 验证集合规则、状态重算和来源映射；feature 验证事务、权限、库存与采购联动；E2E 验证用户主链和展示；mock 验证 WMS 与既有内采/调拨消费者。

## 依赖与 Mock 策略

- 前置切片：无；`blocked_by: []`。
- 外部系统：WMS。合并前以 explicit mock 覆盖创建成功、创建失败、重复成功、超时后查询成功、超时后查询失败。
- 既有下游：库存、付款阶段、内采和调拨链。使用显式 mock 校验逐来源输入，不依赖其他未合入的同版本切片。
- 验证顺序：backend unit → backend feature → frontend unit/component → WMS mock 契约 → E2E 主链与逆向链。

## 业务规则

1. 选择集合至少包含两张发货单，仓库必须一致，每张必须存在剩余可预报数量。
2. 任一筛选条件变化立即清空选择；提交时服务端重新校验完整集合。
3. 运费和货运信息以本次合并预报填写的整票数据为准。
4. 来源商品不跨发货明细、价格、币种、核算维度或供应商合并。
5. 全部关联发货单已发货后才允许整单确认。
6. 基本信息展示去重后的全部供应商；多供应商时商品行展示来源供应商。
7. 取消采用全取消或全禁止，不允许从聚合入库单移除单个发货单。
