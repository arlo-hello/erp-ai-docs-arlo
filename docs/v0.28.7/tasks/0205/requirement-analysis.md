# 采购业务 MCP 与多层级采购需求分析

> 需求版本：v0.28.7
> 任务映射：`0205` ↔ `ERP-205` ↔ `ERP-SLICE-PUR-001`、`ERP-SLICE-PUR-002`、`ERP-SLICE-PUR-003`  
> 输入锚点：ERP-205 用户原始描述；后续十项业务答复；第二轮六项确认；最终确认“调拨仅作为采购链路自动步骤”“采用用户本人 ERP 身份”。

## 1. 一页结论

本期不建设 ERP 内部自动化流程配置模块，而是把现有采购链路中的查询与人工业务操作抽象为 MCP 能力，供外部 Agent 以当前登录用户身份调用。MCP 不复制采购、审批、履约、入库和调拨规则，只调用现有领域能力并返回业务结果。（来源：原始描述“系统基础功能建设已满足业务场景”“调整为使用 MCP”）

核心业务结果是：用户可在任一采购层级基于一张或多张同采购订单的采购入库单，创建并提交下一层内部采购单；系统继续沿用飞书人工审批、内部采购自动生成 B2B 订单以及采购链路自动调拨。用户可通过 Agent 完成未自动履约的 B2B 订单、发货、采购入库和自动调拨的人工确认，形成可追溯的 A→B→C 或 A→B→A 链路。（来源：用户答复1、5、7及第二轮确认1至6）

设计树 frontier 已为空，业务决策已关闭；剩余工作均为现有接口、字段、权限和状态的技术事实核对。

## 4. 六维分析

| 维度 | 结论 | 需求依据 |
|---|---|---|
| 完整性 | 主链覆盖采购创建、提交、审批查询、B2B履约、发货、入库、自动调拨和流水查询；独立调拨明确排除 | 原始描述；用户答复1、7、8；最终确认 |
| 清晰度 | 多层采购定义为“入库明细驱动的下一层内部采购”，而非一次性采购计划 | 用户答复2、3；第二轮确认1 |
| 可行性 | 现有模型已具备采购审批状态、部分收货状态、入库明细来源关系、内采-B2B关系及来源入库单关联调拨 | 代码侦察：采购、入库、内采关系、B2B履约和中转调拨模型/服务 |
| 一致性 | MCP必须复用现有服务和状态校验，不能绕过飞书审批或重复创建自动调拨 | 用户答复1、8；最终确认 |
| 可测试性 | 查询、内采创建提交、B2B与自动调拨接续可拆成三个独立/集成切片 | 第二轮确认4至6 |
| 可追溯性 | 每张目标内采单需保存根采购、直接来源采购、来源入库单及明细、层级、用户和请求标识 | 多层采购 A→B→C 描述；第二轮确认1 |

## 5. 现有能力事实

| 能力 | 已验证事实 | 产品结论 |
|---|---|---|
| 采购状态 | 采购单区分待审批、审批中、通过、不通过、撤销；采购状态区分创建、完成、取消 | MCP提交后只查询审批结果，不提供审批 |
| 部分入库 | 采购入库存在待入库、部分收货、已入库、已取消状态 | 部分收货可作为下一层内采来源，但按实际入库数量计算可用量 |
| 入库追溯 | 入库明细关系可关联采购单、采购商品行、发货单和入库单 | 支持同采购订单多张入库单逐明细合并预览 |
| 内采与B2B | 内部采购关系对象关联采购单和B2B订单 | MCP可从采购单稳定查询关联B2B订单 |
| B2B履约 | 已有履约创建、推送、出库确认及状态查询能力 | 对外抽象为预览、执行、状态查询等原子工具 |
| 自动调拨 | 采购入库中转服务自动创建调拨，并记录来源采购入库单和调拨号 | MCP只查询并处理已有调拨，不提供新建调拨 |
| 入库确认 | 采购入库确认会写实际数量、入库完成状态及后续自动链 | MCP确认前必须展示实际数量并二次确认 |
| 逆向能力 | 采购、入库、B2B履约、调拨均已有部分取消入口，但状态限制不同 | 不提供通用“回滚”；逐工具暴露现有合法操作 |

## 6. 核心不变量与风险

| ID | 不变量/风险 | 控制要求 |
|---|---|---|
| R01 | 重复调用生成重复采购或履约单 | 所有写工具强制客户端请求标识；同用户、工具、业务来源和请求标识返回首次结果 |
| R02 | 多张入库单或并发会话重复使用来源数量 | 按来源入库明细记录已用于续采的数量并原子校验累计值 |
| R03 | A→B→A被误判为循环错误 | 以来源单据链和请求标识判重，不以主体组合判重 |
| R04 | Agent绕过飞书审核 | 提交后只允许查询；发货、履约和入库继续接受现有状态门禁 |
| R05 | 系统已自动建调拨，Agent再次创建 | 本期不提供调拨创建工具，只允许按来源入库查询关联调拨 |
| R06 | Agent猜测主体、仓库、价格或税率 | 缺少关键字段时必须查询候选或向用户追问，不允许模型自行补值 |
| R07 | 超过来源数量仍挂在原链路 | 预览阶段阻止；引导用户创建无来源的新内部采购单 |
| R08 | 页面只保留当前价格，修改前值不可见 | MCP审计记录默认建议值、用户确认值和最终写入值，不要求改造现有页面 |
| R09 | 跨系统调用超时但实际成功 | 先按来源业务键查询结果，再决定是否重试 |
| R10 | 自动与人工处理边界漂移 | MCP查询返回下一可执行动作，不由Agent凭对话推断状态 |

## 7. 自检

- 用户两轮答复和最终两项确认均已逐项进入范围、决策或不变量。
- 未保留旧的自动化流程配置模块作为本期能力。
- 所有调拨能力均限定为采购链路自动调拨处理。
- 采购审核明确排除，用户本人ERP身份明确为唯一授权模式。
- 三个切片均具备验收标准、测试边界、依赖与Mock策略后方可进入评审。
