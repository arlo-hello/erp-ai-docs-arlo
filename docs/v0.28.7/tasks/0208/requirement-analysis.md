# ERP-208 样机出库跨系统自动化需求分析

## 1. 结论与变更基线

**结论：主链路统一为“审批通过即进入独立样机 Workflow，成功才落业务单据并推仓”。** 本次补充替代此前自动/人工双路径设计；飞书表格结构本次不调整。

| 决策 | 最新结论 | 来源 |
|---|---|---|
| D-01 样机字段 | 样机申请新增“物流渠道”，非必填；选项由业务后续提供，不引用 ERP 基础数据物流渠道 | 补充§1–1.1 |
| D-02 唯一路径 | 审批通过后自动推送 ERP 并默认匹配 Workflow；取消“是否自动交运”及“待推送人工补齐”路径 | 补充§1.2–1.2.1 |
| D-03 失败原子性 | Workflow 未命中或推仓失败时不生成样机出库单、出库流水及其他自动单据；仅保存接收/异常记录并同步飞书 | 补充§1.2.2 |
| D-04 独立触发器 | “样机出库”与现有三个订单触发器完全独立，订单条件组不得复用 | 补充§2；代码侦察 |
| D-05 条件组 | 渠道、样机物流渠道、设备状态、活动、计划、SKU；均来自样机请求，样机物流渠道使用独立选项域 | 补充§2.1 |
| D-06 默认推仓 | 删除动作字段“是否推单至仓库”，Workflow 命中后默认推仓 | 补充§3 |
| D-07 单次 WMS | 不存在 WMS 分批发货，一张 ERP 出库流水最多对应一张 WMS 物流单 | 补充§4 |
| D-08 完成回传 | 样机出库完成后 ERP 主动推送结果至样机系统 | 补充§5 |
| D-09 取消守卫 | 仅关联出库流水全部商品实发数量为 0 时允许样机侧取消；任一商品已出库即禁止 | 补充§6 |
| D-10 级联取消 | 合法取消需取消接收记录、样机出库单、出库流水及尚未实发的仓库任务 | 补充§6.1 |
| D-11 禁止编辑 | 审批通过后样机申请不允许重新编辑，仅允许满足条件时取消 | 补充§6.2 |
| D-12 异常同步边界 | 失败异常同时同步飞书并回传样机系统；样机系统只展示/留痕异常，不改变或阻断正常审批；本次不改飞书表结构 | 补充§1.2.2、§7、对话确认 2026-11-25 |
| D-15 异常恢复 | Workflow 未命中、推仓明确失败或结果未知时终止当前办理；物流通过飞书获知异常并补充或修改 Workflow，随后由样机系统重新推送已审批申请，开启新一轮完整流程 | 对话确认 2026-11-25 |
| D-13 项目权限 | “样机出库”触发器的“项目”字段受 TAP 数据权限约束，每个账号仅可查看和选择其授权项目；保存、更新与发布时服务端再次校验 | 最新补充；代码侦察 |
| D-14 配置分层 | Workflow 触发器与条件使用两个独立配置界面；触发器界面不内嵌条件组，条件界面沿用现有“编辑配置”抽屉结构 | 最新补充及附件原型 |

## 2. 范围

### 2.1 本期包含

- 样机申请审批通过后自动推送 ERP，按申请号与内容指纹幂等接收。
- 全新“样机出库” Workflow 对象、触发器、六个条件属性及独立执行器；触发器项目选择沿用 TAP 数据权限。
- Workflow 命中后按动作配置生成单一 ERP 单据链并默认推送仓库。
- Workflow 未命中、明确推仓失败和结果未知的接收记录、异常审计及飞书同步。
- 上述异常同步飞书并回传样机系统，但不影响样机申请正常审批；异常修复后不续跑原接收记录，由样机系统重新推送已审批申请。
- 单一 WMS 物流单关联、出库完成状态与完成结果主动回传样机系统。
- 零实发取消守卫及全链路级联取消。

### 2.2 本期不包含

- “是否自动交运”字段、待推送人工补齐路径及人工补字段后推仓。
- “是否推单至仓库”动作开关及不推仓自动完成出库逻辑。
- 审批通过后的重新编辑、编辑后取消旧链并重建新链。
- WMS 分批发货、多 WMS 单聚合、部分成功汇总。
- 复用订单触发器条件组或 ERP 基础数据物流渠道作为样机物流渠道选项。
- 飞书表字段、分组、视图及枚举调整。

## 3. 现状侦察

| 能力 | 代码事实 | 需求差异 |
|---|---|---|
| Workflow 元数据 | `wf_triggers`、`wf_trigger_actions`、`wf_object_attributes` 分模型保存触发器、动作和条件属性 | 可扩展，但需新增独立 SampleOutbound 对象族 |
| 现有执行器 | `RunFlow` 仅在订单属性与出库属性间分流；动作只实例化 OrderAction/OutboundAction | 样机条件与动作需独立处理器，不能挂订单对象 |
| 最终处理 | `finalTriggerFlowFunc` 仅覆盖订单预售、履约、活动和出库物流 | 样机触发器必须新增独立 final handler |
| 条件执行 | `Operator::judge` 目前按订单或出库属性判断 | 六个样机条件属性需独立 Attribute/Operator |
| 样机出库 | 既有其他出库建单与推仓能力可作为底层领域服务 | 只有 Workflow 成功且仓库受理后才提交业务单据 |
| WMS 关联 | 既有出库流水包含单值 WMS 单号 | 符合本次单一 WMS 物流单边界，无需 1:N 新模型 |
| Workflow 项目枚举 | `EnumsController::projects()` 查询项目时调用 `Helper::applyTapDataPermissions($query, 'draft.customer.owner')` | 样机出库触发器沿用该受控枚举，并在保存/发布时防止绕过权限提交 |

## 4. 六维分析

| 维度 | 结论 |
|---|---|
| 完整性 | 覆盖接收、匹配、推仓、失败不落单、完成回传、零实发取消和级联取消 |
| 清晰度 | 样机物流渠道与 ERP 物流渠道分属不同数据域；名称相同但编码和值域禁止混用 |
| 可行性 | Workflow 框架可扩展；样机对象、条件、动作和最终处理均为新增实现 |
| 一致性 | 审批通过后只有自动 Workflow 一条路径；失败只留接收/异常事实，不产生半链单据 |
| 可测试性 | 每个分支均有 feature/E2E、WMS mock、样机系统 mock 或 TAP 权限 mock |
| 可追溯性 | D-01～D-14 均回链本次补充、附件原型或代码事实 |

## 5. 跨域影响与数据

| 域 | 影响 |
|---|---|
| ORD | 样机请求接收、独立 Workflow 对象、条件匹配、动作编排、幂等与失败原子性 |
| IMS | 单一出库流水/WMS 物流单、库存执行事实、零实发取消守卫 |
| PLAT | 飞书异常同步、样机系统异常回传、出库完成回传样机系统、同步补偿 |

建议接收记录保存原请求快照、六个条件值、Workflow 版本、命中结果、WMS 请求幂等键、异常码和完成回传状态。样机物流渠道按外部编码/名称原样留存并维护独立选项表或配置，不与 ERP 基础物流渠道建立外键。
