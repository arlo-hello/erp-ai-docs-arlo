# ERP-208 样机出库跨系统自动化需求分析

## 1. 来源与结论

**结论：需求可行，边界已关闭，可以进入产品方案。**事实源为《样机出库自动化及交运规则—业务需求文档》§1–§8，以及 ERP-208 评论中 Q1–Q6 的业务确认。

| 决策 | 结论 | 来源 |
|---|---|---|

## 2. 范围

### 2.1 本期包含

- 样机申请接收、幂等保存与来源关联。
- “是否自动交运”分流。
- 自动 Workflow 匹配、样机出库推仓动作及异常回传。
- 非自动路径生成“待推送”样机出库单、编辑补齐、人工推送。
- 飞书全量请求、进度、异常、办理结果同步。
- 一张 ERP 出库流水关联多张 WMS 发货单、运单和实际数量。
- 变更、重推、取消、结果不明、部分出库的防重与补偿。
- 审批通过自动推送、零实发编辑/取消守卫、全链路级联取消与编辑后重新审批推送。

### 2.2 本期不包含

- 飞书内审批或点击决定是否执行 Workflow。
- 主动把一张样机申请拆为多张 ERP 样机出库单。
- 改变样机系统或 ERP 现有字段编辑权限。
- 自动替换商品、货况、主体、销售渠道。
- 改造 SMP 审核、RMA 退货或 AfterShip 的既有业务规则。

## 4. 六维分析

| 维度 | 结论 |
|---|---|
| 完整性 | 覆盖审批触发、自动、人工、重推、零实发编辑/取消、结果未知、部分出库和同步失败 |
| 清晰度 | “待推动”统一规范为“待推送”；“是否自动交运”是唯一分流字段 |
| 可行性 | 既有建单、推仓、Workflow 可复用；飞书同步与 WMS 1:N 关系需新增 |
| 一致性 | ERP 是状态权威源；飞书不直接改业务事实，避免三方冲突 |
| 可测试性 | 每条 AC 指定 unit、feature、E2E 或显式 mock |
| 可追溯性 | 决策 D-01～D-12 均回链需求段落或 Issue 确认 |

## 5. 跨域影响与 DDL

| 域 | 影响 |
|---|---|
| ORD | 样机申请接收、分流、Workflow、状态与幂等 |

建议新增 `sample_outbound_requests` 保存外部请求、版本、分流、状态和幂等键；新增 `ims_outbound_wms_orders` 保存 `outbound_no + wms_outbound_no + status + actual_qty + tracking_number` 的 1:N 关系；新增同步任务表保存飞书/样机回传的幂等与重试状态。最终表名由技术方案确认，但基数与唯一约束不得改变。
