## 4. 变更影响与风险

| 风险 | 事实 | 处理 |
|---|---|---|
| 兼容字段漂移 | 当前服务把 `entity_type` 映射为主体类型，且请求必填 | 接口取消必填；保存时不再用首个角色覆盖；保留旧值只读兼容 |
| 删除漏检 | 当前动态扫描仅检查候选字符串列，整数外键和新增异名列可能漏检 | 建立显式引用注册表/引用查询契约；feature 测试覆盖有引用与无引用 |
| 停用穿透 | 只改主数据页无法阻止其他模块继续选择 | 所有“新业务候选集”统一过滤停用实体；历史详情按编码回显不套过滤 |
| 并发覆盖 | PRD要求检测并发更新，现有保存未体现版本条件 | 引入版本戳或更新时间条件更新，冲突返回统一业务错误 |
| 子记录身份丢失 | 联系人/账户同步当前采用先删后建 | 方案要求事务原子性；审计或外部引用存在时改为按标识差量同步 |

## 5. 数据与跨域影响

- 平台域：主体、角色、联系人、账户、账期、状态及权限是唯一写入边界。
- 采购/订单/库存/财务域：本期仅盘点引用并执行“新业务排除停用、历史按快照展示、删除前阻断”，不改业务流程（Issue 决策3）。
- DDL：优先复用现有表；并发控制若无可用更新时间条件，则新增版本号。`entity_type` 不删除、不迁移旧数据（Issue 决策1）。
