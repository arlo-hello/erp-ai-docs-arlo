# ERP-189 需求分析

## 1. 需求范围

**结论：在物流渠道维护可空的体积重系数，并让自动履约工作流按实重与体积重较大值判断；缺少计算要素时阻断本次自动履约并明确提示。**

| 范围 | 结论 | 来源 |
|---|---|---|
| 物流渠道配置 | 新增“体积重系数”，正整数、最多 10 位、非必填 | 需求第1条；用户答复 Q2 |
| 工作流条件 | 新增“max（实重，体积重）”，阈值为 0.00 至 99,999,999.99 | 需求第2条；用户答复 Q4 |
| 计算规则 | 实重为 SKU 重量乘履约数量之和；体积重为 SKU 长宽高乘履约数量之和除以渠道系数 | 需求第3条 |
| 运行时异常 | 系数、SKU 重量或长宽高缺失、为 0 或非法时，条件判定失败，停止本条自动履约动作并提示具体原因 | 用户答复 Q2、Q3 |
| 审计 | 每次执行读取当前系数，保存系数、实重、体积重、最终计费重量快照 | 用户答复 Q6 |
| 不包含 | 不改销售渠道；不批量回填历史渠道；不改变其他工作流条件 | 用户答复 Q1、Q2 |

## 2. Open Decisions Closed

| 决策 | 结论 | 来源 | 影响域 |
|---|---|---|---|
| Q1 字段归属 | 仓库下的物流渠道；履约按仓库和物流渠道读取 | 用户答复“与推荐答案一致” | 物流渠道、履约 |
| Q2 必填与历史兼容 | 非必填；历史空值仍可配置新条件，实际自动履约时缺系数则异常提示并停止动作 | 用户明确答复 | 存量数据、异常处理 |
| Q3 商品数据异常 | 缺失、0、非法均不得按 0 继续计算 | 用户答复“与推荐答案一致” | 商品、工作流 |
| Q4 阈值范围 | 0.00 至 99,999,999.99，保存为两位小数 | 用户答复“与推荐答案一致” | 表单、校验 |
| Q5 精度 | 中间体积重保留四位，取较大值后四舍五入两位比较 | 用户答复“与推荐答案一致” | 计算、测试 |
| Q6 读取时点 | 每次执行读取当前值并保存计算快照 | 用户答复“与推荐答案一致” | 并发、审计 |

## 3. 现状与可行性

现有工作流已分别按商品主数据和履约数量计算总重量、总体积，且支持大于、大于等于、小于、小于等于比较；物流渠道当前没有体积重系数字段。因此属于现有履约规则能力的增量扩展，技术上可行。主要风险是历史渠道空值与商品尺寸脏数据，均通过运行时前置校验阻断，避免静默使用 0。

## 4. 跨域影响与数据变更

| 域 | 影响 | 数据变更 |
|---|---|---|
| 平台/物流配置 | 物流渠道编辑新增字段 | 物流渠道表新增可空正整数体积重系数 |
| 商品 | 只读重量、长、宽、高 | 无 |
| 订单/履约 | 新增计费重量条件计算与快照 | 工作流历史记录扩展计算明细；具体存储复用方案由技术设计确认 |
| 库存、财务、售后、采购 | 无状态或金额变更 | 无 |
