# 履约申报规则精细化需求分析

> 任务映射：`0185` ↔ `ERP-185` ↔ `ERP-SLICE-ORD-001`
> 输入：ERP-185 需求§1至§5、Clarification Round 1 的 Q1 至 Q8 及用户逐项确认。

## 1. 范围结论

| 结论 | 范围 | 来源 |
|---|---|---|
| 申报比例支持 `0.1%～100.0%`，步长 `0.1%`，禁止 0 | 本期 | 需求§1；确认 Q4 |
| workflow 新增物流渠道条件，条件组合沿用现有 AND/OR | 本期 | 需求§2；已确认 Q5 |
| 物流渠道选项按已选发货仓库级联，换仓后清理失效渠道 | 本期 | Q5 追问及澄清回复 |
| 履约动作可选择“申报比例”或“固定总额”，两种方式互斥 | 本期 | 需求§3；确认 Q1 |
| 固定金额是单张履约单申报总额，按履约数量占比分配到 SKU 行 | 本期 | 需求§4；确认 Q1、Q2 |
| 前 N-1 行截断，最后一行按履约行 ID 升序承接尾差 | 本期 | 确认 Q3 |
| 权重为 0、多币种或币种为空时规则失败并进入人工处理 | 本期 | 确认 Q2、Q8 |
| 拆单、换仓后每张新履约单重新命中；推仓后冻结快照 | 本期 | 确认 Q7 |
| 目的国免税阈值维护与自动校验不在本期 | 不包含 | 需求背景只要求“不超过区间”，需求§1至§4未要求建设税则主数据 |

## 2. Open Decisions Closed

| 决策 | 结论 | 来源 | 影响域 |
|---|---|---|---|
| 固定金额口径 | 单张履约单申报总额 | 确认 Q1 | 订单、履约 |
| 分摊权重 | 以履约数量占比计算；总履约数量为 0 时失败 | 确认 Q2 | 履约行金额 |
| 精度与尾差 | 前 N-1 行截断，最后一行承接尾差；履约行 ID 升序 | 确认 Q3 | 金额守恒、幂等 |
| 比例输入 | `0.1%～100.0%`，步长 `0.1%`，0 非法 | 确认 Q4 | 前后端校验 |
| 条件组合 | 复用 workflow AND/OR，不新增固定三维关系 | 已确认 Q5 | workflow |
| 执行时序 | 先确定仓库与物流渠道，再执行含渠道条件的申报规则 | 确认 Q6 | 规则编排 |
| 重算与冻结 | 新履约单重新计算；推仓后冻结，修改须取消并重建 | 确认 Q7 | 拆单、换仓、审计 |
| 币种 | 沿用履约行申报币种；空币种或多币种失败 | 确认 Q8 | 履约、仓库接口 |

设计树 frontier 为空。Q2 的“产品 SKU 占比”按同句给出的“固定总额/履约数量”解释为数量占比：设固定总额为 `D`、有效行数量为 `q_i`、总数量 `Q=Σq_i`；`Q=0` 失败。前 N-1 行按系统申报金额精度向下截断其分摊额，最后一行分摊额为 `D-Σ前序分摊额`，行单价为“行分摊额/该行数量”。该表达不改变确认口径，只将其转成可验证算法。

## 5. 影响与风险

| 风险 | 影响 | 处理 |
|---|---|---|
| 固定总额被误当 SKU 单价 | 总申报额倍增 | 动作字段明确命名“履约单固定申报总额”，服务端以总额守恒校验 |
| 尾差与行单价精度冲突 | 最后一行反算后无法精确守恒 | 以行金额守恒为最高约束，技术设计明确存储/传输精度 |
| 规则执行时渠道尚未生成 | 条件永不命中或循环依赖 | 编排校验要求渠道条件位于选仓选渠道之后（确认 Q6） |
| 换仓保留旧渠道 | 选项与仓库不匹配 | 配置端换仓立即清空；服务端保存时复核绑定关系 |
| 拆单重复分摊 | 子单合计漂移 | 每张新履约单独立以自己的总额与数量重新计算（确认 Q7） |
| 已推仓数据被覆盖 | ERP 与仓库申报不一致 | 已推仓快照冻结；取消并重建后才能应用新规则（确认 Q7） |

## 6. 跨域与数据结论

- 订单/履约域：workflow 条件、履约动作、拆单换仓、履约行申报值和异常处理直接受影响。
- 仓库/物流域：复用仓库—物流渠道绑定数据源；推仓接口消费冻结后的申报快照。
- 商品域：比例模式继续读取产品申报价；固定总额模式不以产品申报价作为权重。
- DDL：产品方案不预设新增业务表。动作配置结构需要新增“申报方式、固定总额”；是否落库新列由技术方案基于现有 workflow 字段存储确定。
