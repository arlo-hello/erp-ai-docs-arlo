## 2. Open Decisions Closed

| 决策 | 结论 | 来源 | 影响域 |
|---|---|---|---|

| 精度与尾差 | 所有履约行采用截断法，不设置尾差承接行 | 2026-11-04 对 Q3 的调整 | 计算、幂等 |

| 条件组合 | 复用 workflow AND/OR，不新增固定三维关系 | 已确认 Q5 | workflow |
| 条件依赖 | 物流渠道是否可选只取决于同一条件组中是否已有选值的发货仓库条件，与条件组 AND/OR 无关 | 2026-11-04 PR 纠偏说明§1 | 条件编辑器、保存校验 |
| 重算与冻结 | 新履约单重新计算；推仓后冻结，修改须取消并重建 | 确认 Q7 | 拆单、换仓、审计 |

设计树 frontier 为空。此前将“产品 SKU 占比”解释为按履约数量自动计算，属于无来源派生，现按 PR 纠偏说明撤销。固定金额模式保存 SKU 与固定申报占比；运行时按 `SKU 分配金额=固定金额×SKU占比/100`、`SKU申报单价=SKU分配金额/该 SKU 履约总数量` 计算，并对落到各履约行的申报值全部截断。占比合计必须为 100，确保配置语义完整；因 Q3 明确全部截断，计算结果允许小于固定金额，不再以末行补差强制守恒。

## 5. 影响与风险

| 风险 | 影响 | 处理 |
|---|---|---|
| 固定金额被误当 SKU 单价 | 总申报额倍增 | 动作字段明确固定金额是“履约单申报总额”，按 SKU 占比计算申报单价 |
| 全行截断产生余量 | 计算结果可能小于固定金额 | 按 Q3 调整接受截断余量；不自动补给任一履约行，测试记录截断前后差额 |
| 将仓库依赖误做成执行时序 | 扩大 workflow 引擎改造范围 | 只在同一条件组的配置与保存阶段校验“已选仓库后才可选渠道” |
| 换仓保留旧渠道 | 选项与仓库不匹配 | 配置端换仓立即清空；服务端保存时复核绑定关系 |
| 拆单重复分摊 | 子单合计漂移 | 每张新履约单独立以自己的总额与数量重新计算（确认 Q7） |
| 已推仓数据被覆盖 | ERP 与仓库申报不一致 | 已推仓快照冻结；取消并重建后才能应用新规则（确认 Q7） |

## 6. 跨域与数据结论

- 订单/履约域：workflow 条件、履约动作、拆单换仓、履约行申报值和异常处理直接受影响。
- 仓库/物流域：复用仓库—物流渠道绑定数据源；推仓接口消费冻结后的申报快照。
- 商品域：比例模式继续读取产品申报价；固定金额模式通过启用商品模糊搜索建立 SKU 占比配置，不以产品申报价或履约数量自动生成占比。
- DDL：产品方案不预设新增业务表。动作配置结构需要新增“申报方式、固定金额、SKU 固定申报占比列表”；是否落库新列由技术方案基于现有 workflow 字段存储确定。
