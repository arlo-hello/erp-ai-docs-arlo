## 阶段5：功能与规则设计

### 5.1 workflow 条件

- 条件组合完全沿用现有 AND/OR；仓库、目的国家、物流渠道均为普通条件。（已确认 Q5）
- 物流渠道条件仅在同一条件组已存在且已选值的“发货仓库”条件时可选数据；此规则与条件组采用 AND 或 OR 无关。（2026-11-04 PR 纠偏说明§1）
- 物流渠道仅显示该仓库绑定且启用的渠道；仓库条件删除、清空或换值时立即清空已选渠道，服务端保存时复核同组依赖及仓库—渠道绑定。
- 修改仓库后清空不属于新仓库的已选渠道；服务端保存时再次校验仓库—渠道绑定。
- 本期不新增“先确定仓库与渠道再评估规则”的执行编排；运行时继续使用现有 workflow 条件求值机制。（2026-11-04 PR 纠偏说明“基于已完成 workflow 开发”）
- 条件节点独立展示描述、包含内容、关系（且/或）、新增条件、删除全部、条件字段、计算符号、输入值和删除条件行；“物流渠道”仅作为条件字段选项新增。（2026-11-04 第二轮 PR 纠偏说明§2及附件）
- 当条件字段选择“物流渠道”时，计算符号下拉仅提供“等于（=）”和“不等于（≠）”，不得出现大于、小于、包含或其他计算符号。（2026-11-04 第三轮 PR 纠偏说明）

### 5.2 申报动作

履约动作是独立动作节点，不承载描述、且/或关系、条件字段、计算符号、条件输入、条件组新增或条件组删除。无论申报方式为何，仓库、物流、条款、申报方式、签名服务、包材六个字段固定展示。（2026-11-04 第二轮 PR 纠偏说明§1）

| 字段 | 规则 |
|---|---|
| 申报方式 | 必填，单选“比例申报/固定金额” |
| 申报比例 | 方式为比例时必填；支持填写到小数点后1位；填写范围、0值合法性及其他校验沿用系统现状，不在本次调整 |
| 固定申报金额（USD） | 方式为固定金额时必填；必须大于0；最多两位小数；固定金额全链路统一 USD，不沿用履约行原币种 |
| 分类分摊条件组 | 固定金额时至少一组；每组由“分类分摊方式+产品分类分摊明细”组成；支持新增、删除并保存显示顺序 |
| 分类分摊方式 | 每个条件组内必填，单选“人工输入固定值/占总申报金额百分比” |
| 产品分类 | 条件组明细左列，组内必填且不可重复；匹配范围包含所选分类自身及全部层级子分类 |
| 分摊值 | 每组独立校验：固定值模式合计等于固定总金额；百分比模式每项 `0.1～100` 且合计为100% |
| SKU 分摊方式 | 每个分类行右侧必填单选“按 pcs 直接均摊/按销售价格浮动分摊” |
| 非当前方式字段 | 隐藏、清空且服务端忽略，避免双值冲突 |

### 5.3 固定金额算法

设当前分类申报金额为 `A_c`，当前分类（含全部子分类）的商品总数量为 `Q_c`、全部 SKU 行销售金额之和为 `S_c`；当前 SKU 为 `i`，其销售数量为 `q_i`、行销售金额为 `L_i`。

1. 保存配置时至少有一个条件组；每组独立校验产品分类无重复。人工固定值模式下 `Σv_c=D`；百分比模式下每项 `0.1～100` 且 `Σv_c=100`。条件组保存稳定顺序。（2026-11-06 业务调研变更说明§2.1；2026-11-10 多条件组补充）
2. 运行时按条件组顺序逐组检查。对组内分类递归展开全部子分类，以“所选分类+全部后代分类”的编码集合匹配履约商品；只有当前履约单全部商品均被该组明细覆盖时，该组才完整匹配。（2026-11-06 补充§2.3.1；2026-11-10 多条件组补充）
3. 首个完整匹配组生效并立即停止后续组匹配；仅部分覆盖的组不产生结果并继续下一组。全部条件组都无法完整匹配时，整体失败且不产生部分写入，抛出“{履约单号}履约单不符合固定申报金额配置条件，请检查”；`{履约单号}` 运行时替换为当前履约单号。（2026-11-10 多条件组补充、异常文案补充）
4. 按 pcs 分摊：每件商品申报金额 `U=A_c/Q_c`。（2026-11-06 补充§2.2）
5. 按销售价浮动分摊：当前 SKU 行申报金额 `R_i=A_c×(L_i/S_c)`；当前 SKU 单件申报金额 `U_i=R_i/q_i`，即 `U_i=[A_c×(L_i/S_c)]/q_i`。旧公式 `A_c×(S_c/S_f)÷Q_c` 撤销。（2026-11-10 销售价浮动公式更正）
6. 两种分摊遇到除不尽时均按系统申报金额精度截断 `U`，禁止四舍五入且不设置末行承差；把结果回写到当前履约商品的申报金额字段，并在履约单商品明细展示。（2026-11-06 补充§2；2026-11-07 截断规则补充）
7. workflow 命中和结果回写成功后，任一履约商品申报金额为0时不回滚命中结果；用户推仓时立即中断，抛出“缺少履约必要信息，请检查物流、条款、申报货值信息。”，且不得调用仓库或继续任何后续流程。（2026-11-06 补充§2.1）
8. 同一输入与同一条件组顺序重复执行必须得到相同结果。
9. 固定金额模式的 `A_c`、`U`、履约商品申报金额、冻结快照与推仓载荷均为 USD；履约来源即使存在其他交易币种，也不得改变固定金额币种或触发旧 Q8 的空/多币种失败。（2026-11-06 固定金额统一 USD 补充）

### 5.8 W03：履约单商品明细

```text
+---------------- 履约单商品明细 -------------------+
| SKU      | 商品名称 | 数量 | 申报金额（USD）       |
| ABC-001  | 商品A    |  2   | 12.34                |
| ABC-002  | 商品B    |  1   | 0.00                 |
|                                                   |
| [推送仓库]                                        |
+---------------------------------------------------+
```

字段“申报金额（USD）”展示 workflow 计算后回写的当前商品结果。点击“推送仓库”时，若任一行申报金额为0，页面展示异常“缺少履约必要信息，请检查物流、条款、申报货值信息。”，不发起仓库请求。

线框自检：条件节点、履约动作节点与履约单商品明细边界独立；三个页面/区块均有字段或按钮规则；`P=3`、`W=3`。

## 阶段6：验收摘要

1. 申报比例支持填写到小数点后1位，两位及以上小数被前后端拒绝；原有最小值、最大值、0值合法性和其他范围校验保持不变，并做既有边界回归。（需求§1；2026-11-10 申报比例范围更正）
2. 条件节点独立展示描述、且/或关系、条件行新增/删除、条件字段、计算符号和输入值；条件选项新增物流渠道，同组没有已选值的发货仓库时不可选择渠道，物流渠道计算符号仅允许“等于（=）”和“不等于（≠）”。（2026-11-04 三轮 PR 纠偏说明及附件）
3. 履约动作节点固定展示仓库、物流、条款、申报方式、签名服务、包材，不展示条件节点字段；比例申报显示比例输入框，固定总金额显示金额输入框及产品分类分摊卡片。（2026-11-04 第二轮 PR 纠偏说明§1；2026-11-06 业务调研变更说明）
4. Q8 撤回；固定申报金额、分类金额、商品申报金额、履约单展示与推仓载荷统一为 USD，非 USD 交易币种不改变该口径。（2026-11-06 固定金额统一 USD 补充）
5. 按 pcs 的商品申报金额等于分类申报金额除以分类商品数量；按销售价浮动时，先按当前 SKU 行销售金额占当前分类全部 SKU 行销售金额之比分配分类固定金额，再除以当前 SKU 销售数量得到 SKU 单件申报金额。（2026-11-06 补充§2.2；2026-11-10 销售价浮动公式更正）
6. 计算结果回写并展示到履约单当前商品申报金额；任一商品为0时 workflow 仍命中成功，但推仓抛出指定异常，仓库请求与所有后续流程均不执行。（2026-11-06 补充§2、§2.1）
7. 拆单和换仓新单独立重算；推仓后无法原地改值，只能取消并重建。（Q7）
8. 固定总金额支持多个“分类分摊方式+产品分类分摊明细”条件组；按显示顺序执行首个完整匹配组，部分匹配组不得写入结果；全部组未匹配时不产生部分写入，并展示“{履约单号}履约单不符合固定申报金额配置条件，请检查”。（2026-11-10 多条件组补充、异常文案补充）
9. pcs 与销售价浮动分摊遇到除不尽时均截断，禁止四舍五入；断言商品申报金额合计不大于 workflow 固定总金额，并覆盖正好整除、除不尽与重复执行。（2026-11-07 截断规则补充）
