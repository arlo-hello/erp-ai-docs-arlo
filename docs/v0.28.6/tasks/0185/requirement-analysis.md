设计树 frontier 为空。全部条件组未匹配时，异常文案确认为“{履约单号}履约单不符合固定申报金额配置条件，请检查”，其中 `{履约单号}` 运行时替换为当前履约单号。2026-11-06 变更已取代“预选 SKU 并配置占比”的旧方案。选中分类覆盖自身及全部层级子分类。按 pcs 时，商品申报金额为“当前分类申报金额÷当前分类商品数量”；按销售价浮动时，先按当前 SKU 行销售金额占当前分类全部 SKU 行销售金额之比分配分类固定金额，再除以当前 SKU 销售数量得到单件申报金额。两种算法除不尽时均截断。多个分类分摊条件组按顺序匹配且只执行首个完整匹配组；全组未命中时整体失败。计算结果回写履约商品并展示；任一结果为0时 workflow 仍命中成功，但推仓中断。（来源：2026-11-10 异常文案补充、销售价浮动公式更正）

## 5. 影响与风险

| 风险 | 影响 | 处理 |
|---|---|---|
| 固定金额被误当 SKU 单价 | 总申报额倍增 | 动作字段明确固定金额是“履约单申报总额”，先分配分类金额，再计算 SKU 申报单价 |
| 固定值与百分比混用 | 分类金额无法守恒 | 一级分摊方式设为动作级单选；固定值合计等于总额，百分比合计等于100% |
| 多组同时可匹配 | 同一商品被重复计算或结果随实现遍历方式漂移 | 条件组保存显式顺序；运行时首个完整匹配即停止，后续组不再执行 |
| 条件组仅覆盖部分商品 | 产生部分写入和申报金额缺口 | 把条件组作为原子规则；部分覆盖视为该组不匹配，先继续后组，全组失败时不写入任何分摊结果 |
| 分类全部 SKU 行销售金额之和为0或缺失 | 销售价浮动公式分母无效 | 作为销售价浮动计算异常处理，不得使用履约单总销售额或 pcs 公式静默降级；技术评审确认异常承载位置 |
| 仅查询直接子分类 | 深层子分类商品漏算 | 递归展开全部层级子分类并以分类编码集合归组 |
| 0值在 workflow 阶段被当作失败 | 与“命中成功、推仓中断”口径冲突 | workflow 保留成功结果；推仓入口逐商品校验并在首个0值处终止 |
| 旧 Q8 仍被实现 | 固定金额可能按履约行币种计算或因多币种失败 | 明确 Q8 已撤回；固定金额全链路只使用 USD，并新增非 USD 履约来源回归 |
| 全行截断产生余量 | 计算结果可能小于固定金额 | 按 Q3 调整接受截断余量；不自动补给任一履约行，测试记录截断前后差额 |
| 将仓库依赖误做成执行时序 | 扩大 workflow 引擎改造范围 | 只在同一条件组的配置与保存阶段校验“已选仓库后才可选渠道” |
| 条件字段与履约动作字段混画 | 前端错误地把两种节点实现为一个表单 | 页面推导表固定为条件节点和履约动作节点两页；分别维护字段表、按钮表与 E2E 验收 |
| 换仓保留旧渠道 | 选项与仓库不匹配 | 配置端换仓立即清空；服务端保存时复核绑定关系 |
| 拆单重复分摊 | 子单合计漂移 | 每张新履约单独立以自己的总额与数量重新计算（确认 Q7） |
| 已推仓数据被覆盖 | ERP 与仓库申报不一致 | 已推仓快照冻结；取消并重建后才能应用新规则（确认 Q7） |

## 6. 跨域与数据结论

- 订单/履约域：workflow 条件节点与履约动作节点保持独立；分摊结果回写并展示在履约商品申报金额；0值在推仓入口阻断。
- 仓库/物流域：复用仓库—物流渠道绑定数据源；固定金额模式推仓接口消费 USD 申报快照。
- 商品域：比例模式继续读取产品申报价；固定金额模式递归读取所选分类及全部子分类，按补充§2.2或§2.3公式计算。
- DDL：产品方案不预设新增业务表。动作配置结构需要新增“申报方式、固定金额、有序分类分摊条件组、组内分类一级分摊方式、产品分类分摊行、SKU 二级分摊方式”；是否落库新列由技术方案基于现有 workflow 字段存储确定。
