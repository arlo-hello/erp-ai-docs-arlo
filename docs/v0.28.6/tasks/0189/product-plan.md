# ERP-189 渠道体积重系数与工作流计费重量产品方案

## 一页结论

**结论：有条件可做，并以“可配置、可计算、可阻断、可追溯”作为同一端到端交付。**

| 问题 | 结论 |
|---|---|
| 本期解决什么 | 物流渠道维护体积重系数；自动履约按实重与体积重较大值判断 |
| 不解决什么 | 不改销售渠道，不强制回填历史渠道，不自动修复商品主数据 |
| 核心设计决策 | 系数可空；运行时缺失则异常阻断；比较值两位小数；执行保存完整快照 |
| 主要风险 | 历史渠道空值、商品尺寸脏数据、配置变更后的复盘 |
| 上线条件 | 配置入口、计算、异常与快照必须同切片通过验收 |

## 读者路线与责任

| 读者 | 重点 | 需确认 |
|---|---|---|
| 业务负责人 | 范围和异常策略 | 缺配置时阻断而非降级 |
| 后端 | 计算、精度、快照 | 权威数据源与异常码 |
| 前端 | 字段和提示 | 输入范围与错误文案 |
| 测试 | 边界矩阵 | 空值、精度、缺 SKU 字段与重试 |

## 1. 背景与目标

需求要求履约选路不再只依赖实重，而能使用物流常见的计费重量。成功标准是：使用该条件时，系统以商品主数据和履约数量计算结果；计算前提不足时不会误执行自动履约，并能定位原因。

## 2. 核心规则

1. 体积重系数属于仓库下物流渠道，非必填；填写时必须是 1 至 9,999,999,999 的整数。
2. 实重为各 SKU 重量乘履约数量之和；总体积为各 SKU 长乘宽乘高乘履约数量之和。
3. 体积重等于总体积除以当前物流渠道体积重系数，中间精度四位。
4. 计费重量取实重和体积重较大值，四舍五入到两位后与阈值比较。
5. 阈值允许 0.00 至 99,999,999.99，保存为两位小数。
6. “max（实重，体积重）”支持大于、大于等于、小于、小于等于、等于、不等于六类比较符。
7. 系数、重量、长、宽、高缺失、为 0、负数或非法时，不判定未命中，而是停止本条自动履约动作并提示具体缺口。
8. 每次执行读取当前系数并保存系数、实重、总体积、体积重、计费重量、比较符、阈值及结果快照。

示例中实重为 2.7 KG，总体积为 12,125 立方厘米，系数 1000 时体积重为 12.125 KG，最终计费重量为 12.13 KG。

## 3. 主链路与异常恢复

运营先维护渠道系数，再在工作流选择计费重量条件。自动履约执行时读取当前渠道和商品数据，前置校验通过后计算并比较；未命中只记录结果，命中才执行后续动作。校验失败时阻断本条动作并记录异常，运营修正渠道或商品数据后可重新触发；历史异常快照不覆盖。

## 4. 数据与接口影响

物流渠道数据新增可空正整数系数；渠道新增、编辑、详情响应包含该字段。工作流条件元数据新增计费重量属性，执行历史能返回计算快照和异常明细。具体接口路径沿用既有渠道和工作流资源，由技术方案确定，不新建平行入口。

## 5. 权限、通知与审计

沿用既有物流渠道编辑权限和工作流编辑权限。异常在自动履约执行结果中即时提示，并写入可查询历史；本需求不新增站外通知。任何重试均新增一次执行记录，以便还原当时使用的渠道系数。

## 6. 验收摘要

| AC | 业务结果 | 验证层级 |
|---|---|---|
| AC-01 | 系数可空，合法整数可保存，非法值被拒绝 | feature |
| AC-02 | 新条件及大于、大于等于、小于、小于等于、等于、不等于六类比较符可配置，阈值边界正确 | feature |
| AC-03 | 示例计算得到实重 2.7、体积重 12.125、计费重量 12.13 | unit |
| AC-04 | 缺系数的历史渠道可保存规则，但自动履约阻断并明确提示 | E2E |
| AC-05 | 任一 SKU 重量或尺寸无效时阻断并定位 SKU 与字段 | E2E |
| AC-06 | 命中、未命中、异常均保存本次计算快照 | feature |
| AC-07 | 其他工作流条件行为不变 | regression |
